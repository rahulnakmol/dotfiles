# T3 Code

T3 Code is application state, not a GNU Stow module. Do **not** symlink or commit `~/.t3`.

## Never track

`~/.t3` contains machine identity and mutable private state, including:

- T3 Connect OAuth and relay credentials;
- signing keys, DPoP proofs, server secrets, and provider credentials;
- `state.sqlite` with projects, threads, messages, sessions, approvals, and absolute workspace paths;
- environment IDs, runtime descriptors, logs, attachments, caches, and worktrees.

These belong in encrypted operational backups, not dotfiles.

## Portable settings

Only intentionally customized, credential-free exports should be stored in this repository:

- `keybindings.json`, after reviewing it for valid command IDs;
- exported environment theme JSON files.

Keep source copies under a future `t3/` configuration directory. Provision them by copying while T3
is stopped, not by Stow symlink: T3 uses atomic replacement and backfills new default keybindings on
upgrade, which can replace a symlink.

The current VPS keybindings file contains generated defaults rather than intentional customizations,
so it is not tracked.

Provider routing and sensitive values remain configured through T3's provider settings and secret
store. A redacted `settings.json` is still machine-specific and must not be committed.
