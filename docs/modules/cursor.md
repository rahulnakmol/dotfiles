# cursor

Cursor editor rules — path-scoped guidance mirroring the Claude rules, so both tools apply the
same conventions to the same file types.

## Key Files

| File | Purpose |
|------|---------|
| `.cursor/rules/000-architecture-core.mdc` | Core architecture principles, always applies |
| `.cursor/rules/010-secrets.md` | Always-on secrets rule, generated from `agent-policy/catalog.json` |
| `.cursor/rules/1XX-*.mdc` | Language rules: python, go, dotnet, typescript |
| `.cursor/rules/1XX-2XX-*.mdc` | Infra/cloud rules: terraform, docker, cloud-gcp, cloud-azure |
| `.cursor/rules/3XX-*.mdc` | agentic-ai, power-platform-dynamics |
| `.cursor/rules/900-responsible-ai-governance.mdc` | Responsible-AI governance |

`010-secrets.md` is regenerated by `node scripts/apply-agent-policy.mjs`; every other rule file is
hand-authored.

## What's not committed

`cli-config.json`, `permissions.json`, and `.cursorignore` are written by
`apply-agent-policy.mjs` against a real local Cursor CLI install — Cursor itself creates
`cli-config.json` on first run, and the policy script only ever patches an existing one. They're
gitignored deliberately (same "generated, not vendored" convention as the skills bootstrap), not
an oversight.

## Dependencies

Cursor.
